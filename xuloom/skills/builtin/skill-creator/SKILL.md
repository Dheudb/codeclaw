# 技能编写

用于用户明确要求创建或修改可复用技能时，不将一次性答案擅自保存为技能。

1. 明确技能服务的任务、适用范围、输入和最终产物；先检查相近的现有技能，避免重复。
2. 默认保存到用户选择的工作区或全局 `.xuloom/skills/<name>/SKILL.md`。名称使用小写字母、数字、单个连字符，且与目录名相同，最多 64 字符。
3. YAML frontmatter 至少包含 name 和 description。描述说明何时使用和何时不使用；正文写具体流程、异常处理与产物验收。
4. 大段参考材料放 references/，可执行的确定性操作放 scripts/，素材放 assets/；按需读取，不复制无关模板。
5. 工具使用 Xuloom 实际提供的名称和接口；不要假设具备 Codex、Claude、云文档或其他产品的专用工具。先发现能力再设计调用。
6. 修改前读取原文件；创建前检查重名。保留私人技能和凭据，不擅自改 EXE 内的公开内置文件。
7. 用实际任务验证触发条件、资源相对路径和输出形式。脚本先做不产生副作用的检查；需要付费服务或外部发布时遵守用户授权。
8. 报告保存路径、使用方式与已验证范围。SKILL.md 指令不构成额外权限，不承诺尚未运行的流程可靠。
