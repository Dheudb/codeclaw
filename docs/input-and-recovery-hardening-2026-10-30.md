# 输入能力、文件撤销与配置事务（2026-10-30）

本轮接续 [beta.18 源码对照](framework-source-comparison-2026-10-30.md)，仍使用其中固定提交的 Codex、Pi、DSH 参考资料，不将参考代码放进分发包。Pi 的 [`read.ts`](https://github.com/earendil-works/pi/blob/f09d01b85e0384647fcab6779d35ab9dabe04be3/packages/coding-agent/src/core/tools/read.ts) 明确区分图片块与文字，并检查模型的 image 输入能力；DSH 的观察版本与无覆盖发布继续作为文件恢复的安全原则。Codex 的执行授权和持久化回执边界继续沿用上一轮结论。

## 本轮修复与新增

### 1. 按模型声明输入能力

设置 → 模型连接 → 模型 ID 下方，增加“当前模型的输入能力”。同一 API 内每个模型分别保存，可声明仅文本、文本与图片，Anthropic 协议还可声明原生文档。未声明就是未知，不根据品牌名、模型名或网关别名猜测。

声明仅文本后，当前图片、历史图片以及文本模型回退都在实际请求前检查。拒绝请求时保留原历史，不静默删除附件，不自动切换模型或 OCR。文件读取工具、MCP 的不支持媒体也明确说明没有发送或理解；保留其中可用的文字。多模态子代理沿父连接和它实际使用的模型 ID 查询各自声明。

配置示例（连接内字段，不是额外配置文件）：

```json
{
  "model_inputs": {
    "my-text-model": ["text"],
    "my-vision-model": ["text", "image"]
  }
}
```

桌面 RPC 使用 `modelInputs`，存盘使用 `model_inputs`。程序自行构造引擎时仍可配置对应连接；未声明能力的服务最终由接口判断。OpenAI Chat 路径尚未实现原生文档协议，直接传 document 块会明确拒绝；普通 PDF 附件仍通过本地文件工具提取文本，不谎称原生读图文 PDF。

### 2. 修复工具图片被字符串化

此前文件工具返回的图片列表会被公共结果序列化为 Python 字符串，MCP 图片也会变成 JSON 文本。附件图片的传输正常，并不能证明工具图片也正常。

现在公共执行入口保留原生 text/image/document 块，OpenAI 转换器将图片转成 `image_url`；MCP 图片转换成同一内部块。文字长输出继续复用现有归档；其他不支持的 MCP 类型保留完整 JSON 文字，不宣称音频等协议已接通。活动预览不写入图片 base64 正文，持久化回执保留实际媒体块。

### 3. 可比较、可恢复的文件工具备份

宿主模式下，`file_write_tool`、`file_edit_tool`、`notebook_edit_tool` 在真正写入前，先把原始字节与修改后预期哈希写到中央会话的 `tool-results/<session>/file-revisions/`。创建文件也有对应记录；备份或意图记录失败时不修改目标文件。子代理记录归属父会话，重启后仍可恢复。

桌面对话中的文件卡片增加“撤销最近一次写入”，点击后确认。每次撤销只恢复该文件最近一次有记录的工具写入，不是回滚整个回合；多次修改需按实际版本顺序处理。界面原增删统计保留当时的执行事实，文件预览读取最新磁盘内容。

程序接口：`await engine.undo_file(revision_id)`；CLI：`/undo <revision_id>`；桌面 RPC：`files.undo`（需要 `confirm: true`）。修订 ID 保存在工具回执 `revision_id` 和文件卡片 `revisionId` 中。它是用户/程序操作，没有新增一个模型工具。

恢复前使用同一写队列和跨进程文件锁，对比当前内容与该次写入的完整 SHA-256。后续已修改就拒绝覆盖；备份损坏也拒绝。恢复成功清除旧读取证据；重复请求能通过当前磁盘状态识别已经恢复。正在执行的回合、目标、子代理或命令不能同时撤销。

边界：旧会话没有原文备份，不能凭差异伪造原文；Shell、REPL、MCP、外部编辑器的任意副作用不在文件工具撤销范围。系统隔离 worker 不写宿主历史，该模式尚不提供文件撤销，不能为了撤销绕过隔离；原文件工具仍在隔离 worker 内执行。恢复保证文件字节，不承诺所有 ACL、所有权和外部副作用回滚。非协作外部进程仍可能在检查后写入，这不是 OS 强制文件事务。

### 4. 配置损坏与并发保存

模型配置不存在时返回空配置；JSON 损坏、类型错误或读取失败时明确报错并保留文件，不再当作空配置覆盖。支持 UTF-8 BOM。

桌面 API 添加/删除/切换，以及 CLI 选择和配置保存，复用现有 OS 锁，在锁内重新读取最新配置、应用变更、原子保存。不同连接的并发新增保留双方修改；同一字段的显式后写仍覆盖先写。`update_config(transform)` 是程序修改配置的事务入口；底层 `save_config` 是完整替换原语，直接调用它不能代替读改写事务。未实现外部编辑器的跨进程强制锁定。

## 轻量化与剩余边界

没有新增全局提示词、模型请求、运行时依赖、Agent 类型或第二套调度器。媒体处理和文件备份各有一个小模块；执行、归档、权限、队列、会话和 OS 锁继续复用。错误信息只在对应失败发生时返回。

这些本地契约通过不等于任意供应商、多小时真实模型流程都已验证。macOS/Linux 原生程序与系统隔离仍需对应平台验证；未知模型能力需要供应商事实或用户声明，框架不能凭空判定。完整 Responses 接口、任意外部副作用撤销、所有框架的逐项功能等同，不是本轮已完成事项。
