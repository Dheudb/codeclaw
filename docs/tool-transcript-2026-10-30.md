# 执行过程与图片回看

本次交付：桌面 `0.1.0-beta.25`，沿用原来的 Windows EXE 路径。

## 展示

- 中间过程使用轻量单行：操作图标、说明、参数摘要、展开箭头。图片、编辑、终端、搜索、文件、网页、子代理、Skill 分别显示对应图标。
- 展开可查看调用参数和返回结果。失败、取消与等待批准仍保留真实状态；不把工具名或回答内容当作成功判断。
- 完成后整轮自动折叠，保留总用时；纯聊天只有用时，没有空的过程折叠区。小于一秒的单次工具操作不额外显示“0秒”。
- 图片结果显示缩略图，点击放大，支持关闭按钮与 Escape。右侧执行活动也能查看同一张图片。

## 图片数据链路

沿用 `file_read_tool` 读取本地图片和已有原生图片回执，不新增模型工具或额外模型请求。支持图片的接口仍收到原生图片块；声明仅支持文本的接口继续走已有的输入能力检查。

本次新增的是界面展示和回看：原生图片按内容 SHA-256 保存到中央会话产物目录的 `tool-results/<session-id>/images/`，执行事件和过程记录只保存引用、名称与尺寸，避免把 base64 混进活动文本。子代理图片归属于现有父会话产物目录。

`media.read` 是桌面只读 RPC，不向模型暴露。它只接受当前会话内的内容 ID，校验大小、格式、尺寸、路径及内容哈希，不接受任意文件路径或自动下载外部 URL。缩略图按需加载；原图被修改或删除后，新保存的图片结果仍可回看。存档失败会显示预览不可用，不篡改模型已收到的工具结果。

这里的“查看图片”是读取与展示已有图像，不是图片生成。[OpenAI 官方 Codex 工具示例](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)同样描述了将本地图片作为图像内容附加给模型的 `view_image` 工具；公开资料不能证明其桌面前端内部实现。
