## 图片数据链路

沿用 `file_read_tool` 读取本地图片和已有原生图片回执，不新增模型工具或额外模型请求。支持图片的接口仍收到原生图片块；声明仅支持文本的接口继续走已有的输入能力检查。

本次新增的是界面展示和回看：原生图片按内容 SHA-256 保存到中央会话产物目录的 `tool-results/<session-id>/images/`，执行事件和过程记录只保存引用、名称与尺寸，避免把 base64 混进活动文本。子代理图片归属于现有父会话产物目录。

`media.read` 是桌面只读 RPC，不向模型暴露。它只接受当前会话内的内容 ID，校验大小、格式、尺寸、路径及内容哈希，不接受任意文件路径或自动下载外部 URL。缩略图按需加载；原图被修改或删除后，新保存的图片结果仍可回看。存档失败会显示预览不可用，不篡改模型已收到的工具结果。

这里的“查看图片”是读取与展示已有图像，不是图片生成。[OpenAI 官方 Codex 工具示例](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)同样描述了将本地图片作为图像内容附加给模型的 `view_image` 工具；公开资料不能证明其桌面前端内部实现。

## beta.27–beta.28：Markdown 回复图片（2026-10-31）

原 Markdown 渲染器对所有图片节点统一输出 `[图片：alt]`，没有使用图片地址。空 alt 会变成一个空的“图片”占位。另一个独立情况是模型输出 `![](zzc)`：它不是有效网址或可识别的图片文件引用，没有真实图片可从中恢复。

本次移除统一占位：HTTP/HTTPS 图片、受限大小的内嵌栅格图片、工作区内的常见本地栅格图片可以展示并点击放大。Markdown 文档中的相对图片路径按该文档目录解析；仍通过原文件预览范围校验，不能凭 `../`、绝对路径或链接逃逸去读取其他目录，只放行工作区文件或本会话实际修改的外部文件。

beta.28 按用户反馈进一步移除无效图片的正文提示：`![](zzc)`、不支持的协议、本地图片缺失或网络图片加载失败均直接省略，不显示“图片引用无效”、错误图标、加载文字或空图片框。只有成功加载的图片可见并可放大。保留原始 Markdown 和历史文件供复制，不伪造图片、不改写模型回复，也不触发模型重试。

图片组件保持稳定身份，聊天刷新不会反复重建图片状态。放大层挂到独立 portal，避免嵌入 Markdown 段落形成无效 HTML；缩略图与放大图均不发送来源页面 Referer。CSP 仅为图片开放 HTTP/HTTPS，不扩大脚本、连接或框架权限。Markdown 本地图片读取当前文件；已有工具图像仍使用保存的历史快照，两者不混淆。
