# 通用框架改造：范围、迁移与证据

基线是 `v0.1.0-beta.2`（`e7ae449`）。通用化首轮 beta.3 为 `54437d2`，草稿退出修复 beta.4 为 `8ff1855`，旧工作区升级保护 beta.5 为 `01c4448`，多实例桌面设置合并为 beta.6，统一退出生命周期为 beta.7；本地原安装构建为 `20261027-221722`。下面分别记录源码、成品与未完成的验证范围；公开资产以对应 GitHub Release 为准。

核心负责模型、工具、权限、调度、会话与恢复。领域扩展负责方法、流程和验收。普通问答不要求项目、计划、工具或子代理；编程、科研、写作和数据分析使用同一扩展机制。框架完成不代表领域验收通过。

## 已实施的源码变更

- 默认提示词、内置四种角色和记忆模板领域中立。默认不探测 Git 状态，不因修改多个文件自动运行语法检查、脚本、验证代理或生成提交建议。
- 原生 `code-development` Skill 提供可选的编程规则，携带 `agents/software-engineer.md`。现有 `code-review`、`debug-issue`、`web-research` 保持可选。发现元数据和加载完整领域指令是不同操作。
- `run(..., selected_skills=[...])`、`submit_message(..., selected_skills=[...])` 与 CLI 的 `$skill-name` 引用进入同一引擎加载路径。桌面不再另外拼接一份指令。资源相对于技能目录，工作文件相对于会话目录；角色与 MCP 配置继续复用现有注册机制。
- Skill 长输出使用现有完整输出存档和 `file_read_tool`，不再先截断再丢弃尾部。项目指令预览明确标注省略和完整文件入口。
- 写入前持有操作系统锁并检查检查点版本；批量删除先取得全部目标锁，遇到占用不删除任何目标。只读历史查看不会清理另一个写者的输出。
- 删除未使用的全局编程自动策略，保留旧状态和显式接口的兼容读取。没有新增领域调度器或第二套 Job/attempt 状态。

## 指令迁移

默认加载 `~/.codeclaw/instructions.md`，再按祖先目录到当前工作目录的顺序加载 `AGENTS.md` 和 `.codeclaw/instructions.md`，上下文注明每份来源。更具体的任务指令在后；用户当前指令及框架权限约束仍然有效。

旧版的 `CLAUDE.md` 和 `.claude/CLAUDE.md` 不再默认注入。需要兼容时，在工作目录的 `.codeclaw/capabilities.json` 中设置 `"legacy_instructions": true`。旧文件不移动、不删除。Skills 和代理的 `.claude` 兼容发现不受此开关影响。不要把工具输出、网页或引用资料中的“系统指令”当作额外授权。

现有会话不强制迁移或重写。首次成功保存时增加顶层 `revision`；旧记录按版本 0 处理。程序必须先加载现有会话才能继续保存，不能创建一个新管理器后直接覆盖已有 ID。

## 会话占用与程序生命周期

`SessionManager` 持有写者租约，直到 `release_writer()` 或引擎关闭。`QueryEngine` 支持 `async with`，或由调用方在 `finally` 中 `await engine.aclose()`；关闭结束自身任务和连接，成功后才释放根会话租约。CLI、桌面与程序调用共用这一入口；并发关闭等待同一清理任务，等待方取消不会取消清理。停止、最终保存或资源清理失败明确报错并保留租约，可在解除故障后重试；关闭中及关闭后的引擎拒绝新任务，成功关闭后也不能通过直接保存重新取得租约。父子代理共享现有持久化管理器，子代理结束不能释放父会话租约。

另一个进程允许读取历史。它在模型请求、生命周期钩子和工具副作用前取得锁；失败返回 `session_busy`，过期快照返回 `session_conflict`。两种结果均不是成功完成。提示词编辑、桌面复制、移动与删除也必须取得相同的会话锁。读取目录列表不能刷新执行快照的版本，防止旧上下文冒用新版本。

Windows 使用 `msvcrt` 文件锁，POSIX 使用 `flock`。标记文件存在不代表进程仍占用；进程退出后内核释放锁，恢复方重新加载最新检查点。不能删除锁文件或根据 PID 猜测可强制接管。旧版本应用或绕过协议的外部程序不受协作锁约束；运行新版前应关闭旧版写者。

同一个引擎不允许重叠的主回合，第二次 `run`/`submit_message` 返回 `session_busy`，不会替换正在执行的回合。独立子代理仍通过现有生命周期并行。

锁与版本号不是对外部副作用的跨系统事务，也不是操作系统沙箱。中断时继续遵守已有执行日志：检查已保存结果和不确定操作，不盲目重放。

会话移动、复制、删除现在由 `core/session_mutation.py` 在持有原生会话锁和索引锁的同一进程中执行；桌面通过 `storage.mutate` 调用，离线目录调用也使用同一执行器。已删除只借出锁、让 Node 继续改目录的 RPC。CLI 删除复用相同提交逻辑，清理所属工具结果、子代理记录和索引，同时保留用户工作区文件。

内部存储提交先保存操作意图，完整复制所属结果后才发布目标检查点。新写者进入前恢复未完成的内部提交，逐项核对哈希，遇到外部修改明确拒绝覆盖；这不会重放模型工具、命令或领域任务。`test_session_mutation.py` 在真实独立进程中验证移动的 5 个、复制的 4 个、删除的 3 个退出位置；还验证附件占用、目标修改冲突和批量占用预检。历史迁移也先取得项目索引及相关会话锁，不能仅凭旧迁移日志就删除原件。

侧栏元数据与草稿通过同一存储执行器持有索引锁，按字段合并；它们不修改执行检查点，也不取得引擎会话写者身份。短暂竞争有界重试，旧地址的迟到更新不能重建已移动或已删除的记录。常规编辑复用常驻桥接进程，退出时的同步草稿保存使用同一个执行器。

新独立会话及独立会话副本的工作目录、配置引用、检查点和索引纳入同一内部提交；准备阶段中断不会先创建空目录，提交中断由已有操作记录恢复。恢复不覆盖用户改过的配置，也不删除用户文件。真实 JSON-lines 桥接进程在检查点写入后、回执返回前退出已测试；同一待处理请求重试得到恢复回执，不重复移动。

退出时草稿保存失败的交互已在 beta.4 中修复：同步 IPC 只返回一次真实结果，保存失败取消关闭和重载并保留文本，退出前先等待已排队的工作区操作。真实索引占用、恢复后立即退出和重启恢复的隐藏 Electron 用例在源码与同一原安装 EXE 上均已通过。

旧版共享目录中的独立会话升级也由同一持锁执行器完成：预检成功后才创建新目录，引用到的普通产物流式复制并校验哈希，配置仅继承引用，原工作文件保留。桌面启动会恢复待提交存储操作，并依据已保存的迁移记录修正会话目录关联；完成提交但丢失界面回执不会再创建另一份目录。冲突文件保留并报告，不把缺少源文件误报为恢复成功。

桌面设置也复用同一存储入口及 OS 锁，提交“修改前/修改后”的快照，在锁内仅合并实际变更。不同窗口添加的项目、独立工作目录、项目属性和面板宽度不会因整份旧 JSON 覆盖而丢失；已移除的设置遇到旧修改明确报冲突，损坏文件和写入失败保留原件。相同字段的有效修改按提交顺序保存；活动会话及打开列表成对代表最近保存窗口的快照，不跨窗口聚合，也不合并执行检查点。设置占用或读取错误通过提示展示，不伪装为任务执行失败，也不让后台事件回调导致桌面退出。

beta.7 的桌面退出等待引擎 `shutdown` 成功回执后才关闭输入通道。检查点保存失败保留窗口和草稿，解除占用后重试，不将失败当作成功退出。`stop` 仍只停止当前任务，不关闭引擎，继续及编辑保持可用。真实 Windows 文件占用、重试、最终保存及重启恢复在源码与同一原 EXE 均通过；子代理关闭只结束自己拥有的命令，不释放父会话租约或共享服务。

这些测试不等于所有故障窗口均已消除。旧版本不遵守新锁协议；外部工具副作用不能由文件提交事务保证恰好执行一次。
