## 验证的故障边界

- 等待任务不调用模型；FIFO 启动，不超过并发上限。
- 取消等待项不会执行任务；结束会话清理运行及等待任务。
- 重启只明确恢复保存的从未启动项；原运行中任务标记中断，不自动重放。重复恢复不重复启动，同 ID 读取沿用现有记录。
- 目录外读写、目录链接跳转和网络连接由 Windows 拒绝；环境中的测试密钥不传入子进程。
- 已授权只读运行时不允许写入；Job 关闭时终止所属后代进程。
- 运行时、凭据或中央执行记录与可写工作目录重叠时拒绝启动。
- 未实现受限后端的 MCP、浏览器、LSP、旧 Shell 和命令 Hook 不在宿主降级执行。

## 修复过程中保留的失败记录

- 初轮 281 项全量出现两项错误：MCP 测试替身缺少新增执行策略字段，以及一次非交互 CLI 的 35 秒时序超时。前者修正测试契约，后者定向及后续全量均通过；第一次失败不计作成功。
- 初版对子目录设置 Package SID 拒绝 ACE 的验收未通过，未采用该方案。最终禁止可写工作区覆盖可信运行时及中央存储；项目配置文件仍属于授权工作区。
- Windows Python 启动需要 `registryRead`；不授予网络或 COM 能力。文件工作进程避免初始化需要网络设备的 Windows asyncio，不通过开放联网权限兼容文件操作。
- 桌面测试发现空 MCP 工具容器类型错误，修正后重新验证实际设置切换。
- 原 EXE 的额外程序入口检查发现 REPL 默认使用宿主当前目录，已修为会话目录；最终完整分片回归及原 EXE 复测均包含该修正。
