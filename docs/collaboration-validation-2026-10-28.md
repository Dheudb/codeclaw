# Solo / Auto / Ultra 本地验收

> 历史验收记录：本文保留 2026-10-28 对应构建的默认值与测试证据，不作为当前配置指南。自 v0.1.0-beta.13 起，Auto / Ultra 默认不设并发数、累计子任务数或共享输出额度；当前接入规则见 [协作档位](capabilities.md#协作档位) 和 [通用执行接口](framework.md)。下文的 3/8 并发、累计配额及后续 1,000,000 tokens 共享额度均是历史行为。

验证日期：2026-10-28。Windows x64，原安装构建 `20261028-144727`。本次不调用远端模型，不发布 GitHub，也不打包私人 Taiyi Skill。

## 实现边界

- 会话独立保存 `solo / auto / ultra`，默认 Auto；CLI、桌面和 Python 宿主复用同一设置。
- 默认并发 0 / 3 / 8，累计子执行额度 0 / 12 / 32，子代理共享输出额度 0 / 16,000 / 64,000 tokens。
- 额度限制在原生派发入口执行；复用启动回执、父子关系、写入锁、任务结果、等待、停止和恢复。
- 原有深度规划与可选独立验证也经过同一授权、配额与生命周期入口；不再直接创建独立引擎绕过限制。
- 子代理保持禁止递归委派。档位不改变审批模式、角色限制、模型思考强度。
- 输出额度使用已有目标预算的预留/结算约定，并同时接受目标总预算约束；包含子代理辅助模型请求。它不等于输入 token 或金额上限。
- 详细配置、恢复和计数语义见 [Skills 与子代理](capabilities.md#协作档位)。

## 后续调整：长输出额度

用户要求将单次输出提高到 64k 后，构建 `20261028-150332` 把 Auto/Ultra 的默认单次响应上限独立设置为 64,000 tokens，每轮共享输出额度提高到 1,000,000 tokens，不再按并发数切分。实际请求仍受模型/API 上限、显式配置和剩余目标/共享预算约束；普通主代理响应的默认上限未改。

本次增量验证：协作、目标预算、子代理故障和提供商协议 **30/30** 通过；原安装内置 Python 的协作测试 **11/11** 通过，包括 8 个请求分别预留 64,000、并发变化不改变单次额度、共享只剩 10,000 时正确下调并拒绝超额预留。此次小幅调整未重跑全量；上文 273 项是前一构建的全量记录。证据为 `desktop/build/subagent-long-output-targeted.log`、`subagent-long-output-installed.log`，更新状态为 `applied`。原 EXE 二进制哈希及四个公开内置 Skill 不变。
